Paso 1 de 5

1. Recepción de Llamada & Validación de Cédula (DNI Módulo 10)

El asesor recibe la llamada o contacto comercial y presiona Ctrl + Alt + N en AsesorDashboard.razor para abrir el formulario modal de captura rápida.

Acciones del Asesor:

  • Ingresa el número de Cédula/DNI y presiona Validar DNI.
  • El backend ejecuta el algoritmo módulo 10 y consulta duplicados en los últimos 30 días en PostgreSQL.
  • Completa nombres, apellidos, teléfono (10 dígitos) y correo electrónico.
API Ejecutada: POST /api/v1/presales/leads ➔ Retorna HTTP 201 Created (Status: New).
Paso 2 de 5

2. Calificación Técnica & Crediticia con Formulario Dinámico

Con el lead en estado New, el asesor hace clic en Calificar Elegibilidad para renderizar el cuestionario JSON de factibilidad técnica y consulta FDW.

Acciones del Asesor:

  • Verifica la cercanía de la caja dispersora (NAP) a la dirección del cliente (< 300 metros).
  • Confirma que el cliente no mantenga deudas activas consultando el esquema legacy_fdw.customers.
  • Guarda las respuestas en el campo qualification_json (JSONB).
API Ejecutada: POST /api/v1/presales/leads/{id}/qualify ➔ Cambia estado a Qualified.
Paso 3 de 5

3. Selección de Plan Comercial & Formalización de la Orden

El asesor hace clic en Generar Orden de Venta y es redirigido a la vista de orden AsesorOrderDetail.razor.

Acciones del Asesor:

  • Selecciona el plan contratado (ej: PLAN-FIBRA-300M - $45.00/mes).
  • Registra la dirección exacta, piso/departamento y referencias de llegada.
  • Se genera automáticamente el número correlativo de orden: SO-2026-08-0042.
API Ejecutada: POST /api/v1/orders ➔ Estado de la orden: PendingDocuments.
Paso 4 de 5

4. Carga Multipart de Adjuntos & Verificación SHA256

El sistema exige dos documentos bloqueantes antes de poder enviar la venta a revisión de supervisión de calidad.

Documentos Requeridos (< 10 MB):

  • Cédula / DNI Frontal y Posterior: Archivo PDF/PNG con legibilidad de número y firma.
  • Contrato Digital Firmado: Archivo PDF con consentimiento de débito o pago.
  • El backend calcula el hash SHA256 inmutable y lo almacena en crm.order_documents.
API Ejecutada: POST /api/v1/orders/{id}/documents (Multipart Form-Data) ➔ HTTP 201 Created.
Paso 5 de 5

5. Envío a Auditoría & Notificación SignalR al Supervisor

Al cumplirse los requisitos bloqueantes, se activa el botón verde Enviar Orden a Auditoría.

Efectos del Envío:

  • La orden cambia al estado PendingAudit.
  • El Hub de SignalR emite una notificación push a la campana del Supervisor de turno en tiempo real.
  • Si el supervisor aprueba (Score ≥ 80), Backoffice activa la orden y la comisión comercial se liquida al asesor.
API Ejecutada: POST /api/v1/orders/{id}/submit-audit ➔ Notificación push WebSocket emitida.
